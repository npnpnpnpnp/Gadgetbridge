# LS7076 / Ultra3 test build

This build adds the alternate FitPro command service used by HiWatchPro,
camera-mode commands, packet reassembly, activity-history requests and corrected
activity parsing. It also adds a local, acknowledged watch-face uploader and an entirely offline
photo/GIF-to-ZIP converter.

## Device validation

The owner confirmed Find watch, camera control and activity sync work with the
test build on 22 September 2026. Watch-face upload has **not** yet been tested on
the watch. The exported display capabilities are:

| Field | Value |
|---|---|
| Display | 240 × 286 |
| Main / matching model | LJ736 / K75 |
| Algorithm | 3 (8-bit face format in HiWatchPro) |
| Format version | 1 |
| Config / screen type / grade | 0 / 0 / 0 |
| Selectable slots | 0 (omit the slot byte; use the default destination) |
| Thumbnail | Not advertised |

The firmware's manufacturer string is LS7076, hardware LJ733_MB_V1.1, firmware
V34869. Those strings are different from the watch-face matching identifiers.
Use the exported display details to identify the face format.

## Install and connect

The debug APK is named **Gadgetbridge LS7076**, with application ID
`nodomain.freeyourgadget.gadgetbridge.ls7076`. It can coexist with the official
app. Stop the other watch companion apps while connecting. Add Ultra3 as FitPro
and select **Don't Pair**. Media/audio pairing is a separate Android connection.

## Create a face from a photo or GIF

1. In the device card, open **Watch faces**. Read display details once if needed.
2. Open **Create watch face**. Choose whether to include the live clock.
3. Tap **Choose image or GIF** and select a PNG, JPEG or GIF.
4. After conversion, tap **Save watch-face ZIP** and choose a location.
5. Later, return to **Watch faces → Choose watch-face package**, select the ZIP,
   and install it.

Conversion runs entirely on the phone, without internet, an account, vendor
credentials or HiWatchPro. After display details have been cached, ZIP creation
also works with the watch disconnected. It does not upload automatically.

Images are centre-cropped to 240 × 286. Transparency is composited on black. The
**Image palette** setting offers the existing 216-colour
RGB565 cube for compatibility, or a 255-colour RGB565 palette built from the most
frequent colours in each image for better photographic detail. **Direct RGB565**
does not make a palette at all: it writes every source pixel as a 16-bit RGB565
value, which is the closest device-supported representation to the original image
or GIF frame. The optional live hours/minutes use original seven-segment
digits on a black strip at the bottom. Turning the clock off produces only the
image/animation. JPEG orientation is read from EXIF.

GIFs are composited by Android's GIF decoder, sampled at up to 10 fps, with at most
80 output frames and 30 seconds. Large source canvases/animations can hit the
additional memory limit sooner. Frames repeat on the watch according to its
firmware; the GIF's finite loop count is not encoded. Variable frame durations
are approximated by sampling. The binary animation interval is provisionally
interpreted as centiseconds; **exact playback speed is not hardware-verified**.

This first converter supports only the exported LJ736/K75, algorithm-3,
format-1, config-0 display. Generated files pass package integrity and structural
tests, but **new face playback, clock rendering and animation timing require
validation on the watch**. Find watch, camera and sync retain their existing paths.

## Install a watch face

1. Open the watch-face action on the device card. Read and export display details
   if you have not already done so.
2. Obtain a **prepared, compatible binary payload**. For this device that means
   the LJ736/K75, 240 × 286, algorithm-3 format. A raw PNG/JPEG/GIF, renamed file, arbitrary
   firmware binary, or face for a different display is not a compatible payload.
3. Package it on the computer, using the exported details:

   ```sh
   python3 tools/fitpro_watchface.py \
     --display /path/to/fitpro-display.properties.txt \
     --binary /path/to/compatible-face.bin \
     --name "My face" \
     --output /path/to/my-face.fitpro.zip
   ```

4. Transfer the resulting ZIP to the phone. In Gadgetbridge's watch-face screen,
   choose **Choose watch-face package**, select it, review the replacement prompt,
   and install. Wait for **Watch face installed**, which requires the watch's final
   success response. Failed or timed-out uploads are reported as failures.

The packager labels the file for the supplied display; it cannot prove that an
unidentified binary really uses that display's encoding. Start with a known-good
face obtained for this exact display. The source face's layout position can be
specified using `--position`; `--custom` sets the custom-photo flag for an already
prepared custom face. This command-line packager does not convert photographs; use the Android
**Create watch face** screen for offline photo/GIF conversion.

For watches advertising selectable slots, `--slot` is **one-based**, as in
HiWatchPro. On this watch, `slots=0` means use the default destination, not that
uploads are unavailable; the app omits the slot field entirely.

HiWatchPro converts custom algorithm-3/4 images through its 8-bit conversion
server. Our converter independently generates the full format-1 catalogue face
container locally, including its own clock digits.
For algorithm 3 with config 0, a fixed catalogue face is sent as its downloaded
binary without the font/thumbnail concatenation used by some other variants.
No face assets or vendor account credentials are included in this source tree.

## Removing faces

No on-watch delete command was found in the inspected HiWatchPro watch-face
code. Its deletion operations remove temporary files from the phone.
The new uploader replaces a downloadable face; it does not delete built-in faces
or erase a slot. No delete or reset workaround is implemented.

## Transfer details

- Service: `6e400801-b5a3-f393-e0a9-e50e24dcca9d`, alongside the original service.
- Write: `6e400002-…`; notify: `6e400003-…`.
- Capabilities: `20/02`; start: `1f/02`; block: `1f/01`; finish: `1f/03`;
  status query/reply: `20/01`.
- 120-byte blocks for config bit 1, otherwise 200 bytes. Packets are fragmented
  into 20-byte ATT writes. Sequence numbers start at 1.
- Block checksum: unsigned-byte sum including the two-byte sequence, modulo
  65536. Finish payload: four-byte file length and four-byte sum. Big endian.
- Status 1000 starts data; 1000 + sequence acknowledges a block. Status 2 is
  accepted only after the finish command. Duplicate acknowledgements do not
  advance the transfer. Status is polled every two seconds; ten seconds without
  forward progress aborts. Reconnect before retrying after a stalled upload.
- Package: ZIP with exactly `watchface.properties` and `watchface.bin`, maximum
  binary size 7 MiB. Compatibility and SHA-256 are checked before uploading.

## Build and tests

Requires Java 21, the Android SDK platform specified in `app/build.gradle`, and
the bundled Gradle wrapper. Point `local.properties` at the SDK.

```sh
./gradlew :app:assembleMainlineDebug
./gradlew :app:testMainlineDebugUnitTest \
  --tests '*FitPro*Test'
```

Protocol tests cover fragmented/coalesced packets, vendor command bytes,
checksums, block boundaries, duplicate and invalid acknowledgements, premature
success, malformed capabilities, package integrity and compatibility checks.
